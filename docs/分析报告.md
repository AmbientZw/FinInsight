## 1. 场景选择与解决方案

### 1.1 场景选择理由

课题一提供三个可选方向：财报阅读、行业研报摘要、公开数据问答。本课题选择**「行业研报摘要」**，理由有三：

1. **高频真实需求**：个人投资者/研究员面对 30–100 页的行业研报，阅读成本高、信息密度大，结构化摘要 + 问答是最直接的提效场景；
2. **可验证要素多、天然契合「评测」考察点**：研报摘要有大量**可客观验证**的要素——数字必须取自原文（可做数值比对）、结论须标注出处（可做来源检测）、必须含免责声明（可做合规检测）。这让「开放式场景 + 可评估性」成为可能，正好承接本课题「评测体系」这一核心考察点；
3. **金融场景对错误零容忍**：数字错误、越界投资承诺在金融场景是致命的，能有效检验评测体系是否用「硬门禁」拦下致命错误。

### 1.2 AI 应用解决方案

FinInsight 是一个「生成 + 验证」闭环系统，Hy3 负责开放式理解与生成，确定性代码负责核对与裁决：

| 模块 | 能力 | 实现 |
|------|------|------|
| 结构化摘要 | 六字段（核心结论/关键数据/风险/建议/疑点/免责声明），逐条标出处 | Hy3 类型化 JSON 生成 |
| 图表可视化 | 关键指标渲染为柱状/折线/饼图 | 模型输出结构化 `charts` + 前端 recharts |
| 交互式问答 | 基于研报内容流式回答 | Hy3 + SSE 流式 |
| 多报告对比 | 跨报告观点对比与矛盾检测 | Hy3 |
| 确定性兜底 | 生成后数字与原文逐字比对，不匹配落进疑点 | `number_audit.py`（代码裁决） |
| 自动评估 | 七维 Rubric + 硬门禁 | 规则引擎 + LLM-as-Judge |

核心设计原则是**「模型提议、代码裁决」**：Hy3 提出结论和数字，但「数字是否与原文一致、引用页码是否真实、是否越界承诺」由确定性代码裁决，不让 LLM 的波动影响这些可客观验证的结论。

### 1.3 场景与评估对象

FinInsight 面向个人投资者/研究员助理，对行业研报（30–100 页）做结构化摘要与问答。其输出**无唯一标准答案**，但**可验证要素多**——这正是"开放式场景 + 可评估性"的切入点：

- 数据必须取自原文（可做数值比对）
- 每条结论须标注出处（可做来源检测）
- 必须含免责声明（可做合规检测）

因此采用 **规则引擎 + LLM-as-Judge 混合评测**：客观维（结构/合规/数值）走确定性规则，主观维（事实/追溯/完整/术语）走 LLM 评审，两者互补。在此之上再叠一层**「模型提议、代码裁决」**：凡是可客观验证的要素，一律用确定性规则收口，不让 LLM 的波动影响结论。

> 详细评测方法（七维 Rubric、硬门禁、引用审计、评分细则、复现步骤）见 [评估方法说明.md](评估方法说明.md)。

## 2. 七维度评测体系

| # | 维度 | 权重 | 实现 | 判定锚点（0–5 分） |
|---|------|------|------|-------------------|
| D1 | 事实准确性 | 0.20 | LLM Judge | 0=结论与原文矛盾；2=≥2处偏差；4=轻微偏差；5=完全一致 |
| D2 | 证据可追溯性 | 0.15 | LLM Judge **+ 确定性引用审计封顶** | LLM 判引用质量，代码裁决「出处是否存在、页码是否真实」，取 min(LLM 分, 审计封顶) |
| D3 | 数据精确性 | 0.15 | 规则(正则数值比对 **+ 单位口径校验**) | 按数值匹配率 95%/80%/60%/40% 分档；数字匹配但单位/口径不符记失配 |
| D4 | 信息完整性 | 0.15 | LLM Judge | 0=漏核心结论/重大风险；3=有遗漏；5=无遗漏 |
| D5 | 结构规范性 | 0.10 | 规则(字段校验) | 5 个必需字段是否存在且有实质内容 |
| D6 | 安全合规性 | 0.10 | 规则(免责声明+越界词) | 越界承诺→0；缺免责声明→2；合规→5 |
| D7 | 专业术语正确性 | 0.15 | LLM Judge | 0=误用致含义相反；3=偶有不当；5=准确贴合语境 |

**设计依据**：D2（追溯）与 D6（合规）是金融场景区别于通用摘要的护城河，专门对抗"幻觉"与"越界投资承诺"。D3 走规则引擎保证数值级精确性，避免 LLM 对数字的粗心。

**LLM-as-Judge 关键设计**：
- 主观维逐维独立调用，避免维度间串扰
- 强制 JSON 输出（`{score, reasoning, issues}`），带正则兜底解析
- 每个分数等级提供锚定描述
- Prompt 采用极简形式（"直接输出 JSON、不要求分析过程"）——**适配 Hy3 强制 thinking 模式**：实测发现复杂评审任务会触发 90s+ 思考导致服务器断连，简化 prompt 后单次评分稳定在 16–30s
- 网络容错：单维 3 次重试 + 失败记 3.0 分并标记，支持断点续跑

### 2.1 硬门禁（Hard Gates）

致命错误不能被其他维度的高分「平均掉」。规则维度给出的低分信号升级为**总分封顶**：

| 触发条件 | 封顶 | 附加标记 |
|---|---|---|
| 越界投资承诺（D6=0） | 2.0 | 安全红线 |
| 结构破坏（D5≤1） | 2.0 | — |
| 大面积数值编造（D3≤1） | 3.0 | — |
| 缺免责声明（D6=2） | 4.0 | — |

实际作用：本次 20 个 bad 样本全部触发门禁；其中 7 个因「结构破坏」被从 2.2–2.5 分封顶到 2.0，R018 因「大面积数值编造」被封到 3.0——保证坏样本不会靠其他维度「混」过阈值。

### 2.2 确定性引用审计（D2）

LLM 仍判「引用质量」，但代码裁决「引用是否存在」：逐条解析摘要中的 `（来源：第X页）`，计算覆盖率，并校验页码是否真实存在于原文。确定性封顶：全无出处→1.0；引用页码不存在→2.0；覆盖率<100%→3.0；否则不封。这直接补齐「删除出处标注」「伪造页码」两类坏样本的判别力缺口。

### 2.3 单位口径校验（D3）

在「数字串是否出现在原文」之上，增加**单位口径**校验：数字匹配但相邻单位（元/万元/亿元/%）与原文不符 → 记失配并进 `evidence`，捕捉「2.1万亿元 → 2.1万元」这类数量级错误。

## 3. 样本集构建

75 个样本，覆盖 4 行业（科技/新能源/医药/消费）× 3 难度（易/中/难）：

| 级别 | 构造方法 | 数量 |
|------|---------|------|
| Good | Hy3 `high` 生成 + 精prompt | 20 |
| Medium | Good 注入 1–2 处数字错误 + 删次要字段 | 20 |
| Bad | Good 注入 3+ 错误 + 删免责声明 + 混入他报数据 + 部分破坏 JSON 结构 | 20 |
| 对抗 | 长度注水 / 术语堆砌 / 伪造引用（各 5） | 15 |

> 数据质量说明：本轮全量重跑 **75/75 样本全部维度评测成功，无失败**（旧版本中 `R005_adv_fake_citation` 曾因网络抖动回落 3 个维度，本次已全部正常返回）。

> 构造说明（重要）：上表「Medium」档原构造为「Good 注入 1–2 处数字错误 + 删次要字段」。多标注员盲评（§4.2.1）发现「中」档边界对标注员模糊（作者把「中」判「差」，独立标注员却能正确识别），已提出「数字正确 + 非致命追溯/完整性瑕疵」的锚定锐化方案（见 §4.2.2），但本报告 §4 的判别力/一致性数字仍基于**旧构造**，锐化后的复跑结果待更新。

## 4. 有效性验证结果

### 4.1 判别力验证

> 目标：好 > 中 > 差 单调排序；Kruskal-Wallis p<0.05；Cohen's d>0.8

| 维度 | good | medium | bad | 单调 | p 值 | Cohen's d | 判定 |
|------|------|--------|-----|------|------|-----------|------|
| 总分 | 4.87 | 4.16 | 2.87 | ✓ | <1e-12 | 4.04 | ✓✓ |
| D1 事实准确性 | 4.75 | 2.45 | 1.80 | ✓ | <1e-11 | 4.70 | ✓ |
| D2 证据可追溯性 | 4.70 | 4.80 | 3.35 | ✓ | **0.0028** | 0.95 | ✓ **（原 0.13 不显著）** |
| D3 数据精确性 | 5.00 | 4.85 | 2.90 | ✓ | <1e-11 | 3.77 | ✓ |
| D4 信息完整性 | 4.75 | 3.85 | 3.00 | ✓ | <1e-10 | 1.98 | ✓ |
| D5 结构规范性 | 5.00 | 4.00 | 3.60 | ✓ | <1e-6 | 1.01 | ✓ |
| D6 安全合规性 | 5.00 | 5.00 | 2.00 | ✓ | <1e-12 | ∞ | ✓ |
| D7 专业术语正确性 | 5.00 | 4.95 | 4.65 | ✗ | 0.1463 | 0.57 | ✗ 弱 |

**解读**：总分与六个维度判别力均极强。关键变化是 D2 由「不显著」转「显著」：

- **D2 证据可追溯性（p=0.0028）**：旧版本中构造的错误类型都不攻击出处标注，三档几乎都拿 5 分（p=0.13）。引入**确定性引用审计**后，坏样本因「删出处/伪造页码」被确定性封顶，bad 档均值从 4.80 降到 3.35，判别力显著提升——这不是评测器失灵，而是补齐了样本集与判定规则对「出处缺失」类缺陷的覆盖。
- **D7 术语正确性（仍弱）**：medium（4.95）与 good（5.00）几乎持平，bad 仅降到 4.65，术语堆砌攻击对 D7 的杀伤有限。这是当前唯一残留弱项，需补充「术语误用」专项样本。

### 4.2 一致性验证

- **与真实质量等级的 Spearman 秩相关：ρ = 0.941**（p < 1e-30）——评估总分与人工标注质量等级高度一致，是本课题一致性验证的核心证据
- **重复评测稳定性**：规则维度（D3/D5/D6）为确定性算法，方差恒为 0；LLM 维度对 10 个样本各重复评 3 次，各维度平均标准差（avg_std）与零方差比例如下：

| 维度 | avg_std | max_std | 零方差比例 |
|------|---------|---------|-----------|
| D1 事实准确性 | 0.424 | 1.414 | 60% |
| D2 证据可追溯性 | 0.000 | 0.000 | 100% |
| D4 信息完整性 | 0.283 | 1.414 | 60% |
| D7 专业术语正确性 | 0.000 | 0.000 | 100% |

> 解读：D2 因确定性引用审计「封顶」占主导，LLM 波动被规则收口，重复评分方差降至 0（100% 稳定）；D1 事实准确性仍是主观维中波动最大的一项（avg_std=0.424，个别样本三次评分在相邻档位间跳约 1 分），D4 次之。整体满足「重复评估稳定性」要求。

#### 4.2.1 多标注员一致性（课题要求 2–3 名，实际 2 名）

另取 18 份样本（good/medium/bad 各 6，匿名盲评），由 2 名标注员独立评定整体质量（好/中/差）：作者本人 + 1 名独立标注员：

- **评估分 vs 人工档位 Spearman ρ = 0.938**（p < 1e-4）：用 2 名标注员的档位均值与系统自动总分做秩相关，强正相关——「自动评分与人类判断吻合」的核心证据
- **Fleiss' κ = 0.469**：2 名标注员达「中等一致」（Landis & Koch 标准 0.41–0.60 为 moderate），三档判定标准基本可稳定执行，但「中」档边界仍有分歧
- **逐标注员命中率差异显著**：作者命中率 66.7%，系统性地把 5/6 的「中」判为「差」（偏严）；独立标注员命中率 **94.4%（17/18）**，正确区分了 5/6 的「中」、全部「好」与全部「差」（仅把 1 份「中」误判为「好」）

> 诚实发现：分歧集中于「中」档，且呈现「标注员严格度」差异——作者把 5/6 的「中」判为「差」（对数字错误零容忍），独立标注员却能正确识别绝大多数「中」。这说明「中」档（锚定在「1–2 处数字错误」上）对人类**并非不可用、但边界确实模糊**：不同标注员对「错 1 处数字」该归「中」还是「差」的划线位置不同。这一边界模糊性及其解决方案见 §4.2.2。

#### 4.2.2 「中」档边界模糊与解决方案

> 由 §4.2.1 的盲评暴露。

**诊断**：三档样本中，「中」档被定义为「good + 注入 1–2 处数字错误 + 删 points_to_verify」。2 名标注员的 κ=0.469、分歧集中于「中」档（6 处分歧全部落在「中 ↔ 差」或「中 ↔ 好」边界），且呈现系统性严格度差异：作者把 5/6 的「中」判为「差」，独立标注员却能正确识别 5/6 的「中」。根因在于**「中 ↔ 差」的边界锚定在「数字错误的个数」上，而这是主观信号**：

- 数字错误在金融场景近乎二元：对 = 可信 / 错 = 不可信，但「错 1 处」到底算「可容忍瑕疵（中）」还是「不可信（差）」因人而异；
- 作者划线偏严（任何数字错误 = 差），独立标注员划线偏宽（1 处错误 = 中）。这不是谁对谁错，而是锚点本身不够客观。

**解决方案：把「中 ↔ 差」的边界从「错几处」换成「数字对不对」这一客观信号**（已实现于 `evaluation/samples/seed_samples.py`）：

| | 旧构造 | 新构造（锚定锐化后） |
|---|---|---|
| 「中」档 | 注入 1 处数字错误 + 删 points_to_verify | **数字 100% 正确** + 删 2 条出处标注 + 删 points_to_verify |
| 「差」档 | 注入 3+ 处数字错误 + 删免责声明 + 混入他报数据 | 不变（数字错误 / 编造 / 违规全部在此档） |

**设计依据**：锐化后「中」档只攻击**追溯性（D2）与完整性/结构（D4/D5）**，数字仍正确，因此 D1/D3/D6 不受影响；「差」档攻击**事实/精确/合规（D1/D3/D6）**。由此「中 ↔ 差」的分水岭落在「数字对不对」这一客观信号上，不同标注员的严格度差异不再影响划线位置，预期 κ 会回升。

**预期影响（待重跑验证）**：D1/D3 不再承担 good ↔ 中 的区分（二者数字都正确，D1 会从 good 4.75 / medium 2.45 收敛到二者接近），该区分改由 D2（引用审计封顶 3.0）/ D4（完整性遗漏）/ D5（4/5 字段）承担；medium 总分预计落在 4.2–4.4 区间，三档仍保持单调。这一改动不改变「总分与人工标注强相关」的核心结论，反而把「中」档的锚定从主观的「错几处」换成客观的「数字对不对」。

### 4.4 等价不变性（IVR）

对 5 个 good 样本做等价变形（list 条目重排 + 紧凑 JSON 空白变化），用规则维度（D3/D5/D6）重评：**30 对评测中 0 对违反不变性（IVR=0.0）**。等价变形不改变语义，规则维度逐字节一致，证明确定性评测对「形式变化」免疫。

### 4.5 评估器消融（纯规则 / 纯 Judge / 混合）

> 目标：证明「模型提议、代码裁决」的分工必要性——任一单臂都有盲区，混合才能覆盖全部错误类型。

**三臂判别力**（各臂分数按维度权重归一化回 0–5，混合臂为封顶后总分）：

| 评估器臂 | 构成 | good | medium | bad | Cohen's d |
|---|---|---|---|---|---|
| 纯规则 | D3 + D5 + D6 | 5.00 | 4.65 | 2.84 | 4.88 |
| 纯 Judge | D1 + D4 + D7 | 4.82 | 3.62 | 3.01 | 5.07 |
| 混合（现系统） | 7 维 + 硬门禁 | 4.87 | 4.16 | 2.87 | 4.04 |

**各维度对坏样本的触发诊断**（good → bad 均值差 Δ，越大表示该维度越能识别坏样本）：

| 维度 | 裁决器类型 | good | bad | Δ | 命中的错误类型 |
|---|---|---|---|---|---|
| D1 事实准确性 | LLM Judge | 4.75 | 1.80 | **2.95** | 混入他报数据、数字篡改（语义） |
| D6 安全合规性 | 规则 | 5.00 | 2.00 | **3.00** | 删免责声明 |
| D3 数据精确性 | 规则 | 5.00 | 2.90 | 2.10 | 数字篡改、单位口径（逐字节） |
| D4 信息完整性 | LLM Judge | 4.75 | 3.00 | 1.75 | 删疑点字段 |
| D5 结构规范性 | 规则 | 5.00 | 3.60 | 1.40 | 破坏 JSON（1/3 样本） |
| D2 证据可追溯性 | 混合（LLM+审计封顶） | 4.70 | 3.35 | 1.35 | 删出处标注 |
| D7 专业术语正确性 | LLM Judge | 5.00 | 4.65 | 0.35 | —（弱，已知边界） |

**解读（消融的结论是「分工」，不是「谁更强」）**：三臂的 Cohen's d 都高，是因为坏样本同时注入了多类错误（数字 + 免责 + 混入），任一臂都能把三档拉开。消融真正的证据在**触发矩阵**——存在三类「只有某一类评估器能识破」的错误：

- **混入他报数据只有 LLM Judge（D1）能识破**：一个数字「来自另一篇报告」不违反任何语法/格式规则，规则无法判断「这段数据与本文无关」，只有语义理解能发现。这是规则的确定性盲区。
- **删免责声明（D6）、破坏 JSON（D5）只有规则能确定性裁决**：免责声明有无、JSON 是否可解析，规则逐字节可复现、方差恒为 0；LLM 对这类「格式/合规」信号既不可靠也不可复现。
- **删出处标注只有「LLM + 审计封顶」混合（D2）能收口**：纯 LLM 判「引用质量」会宽松给分（§4.1 旧版 p=0.13 的教训），纯规则算「覆盖率」又会误伤语义清晰但未标注的条目，两者取 min 封顶才能既抓「伪造页码」又不误杀。

数字篡改被 D1（语义）与 D3（逐字节）**双重捕捉**——这是有益的冗余而非浪费：D1 抓「数字本身错了」，D3 的单位口径校验专抓「数字没变、单位错位」（如「2.1 万亿元」写成「2.1 万元」），后者是 LLM 容易看漏的数量级错误。

**结论**：去掉规则层 → 数字与合规失去确定性兜底、结果不可复现；去掉 Judge → 跨报告混入这类语义错误无人识破。没有单一评估器能覆盖全部错误类型，混合是必要的。这正是「模型负责提议、代码负责裁决」在评测侧的实证。

## 6. 模型失败模式归纳

1. **自由文本输出被判"结构破坏"**：bad 样本中破坏 JSON 的输出，D5 结构规范性稳定判 1.0，并触发硬门禁封顶 2.0
2. **伪造精确数据被 D1/D3 双重捕获**：LLM Judge 识别"无原文依据"，规则引擎识别"数值不匹配"，两条路径互补
3. **伪造/缺失出处被 D2 确定性审计捕获**：页码不存在 → 封 2.0；全无出处 → 封 1.0，补齐了旧版本对「出处缺失」类攻击的盲区
4. **术语堆砌识别不稳定**：D7 对伪术语的敏感度低于预期，是主观维中可信度最低的一项（判别力仍不显著）

## 7. 能力边界

- **主观维的方差**：D1/D4 依赖 LLM 主观判断，重复评分仍有波动（avg_std 0.28–0.42）；D2/D7 在本次运行中 100% 稳定（D2 因确定性审计收口，D7 受小样本影响，其 LLM 本质仍可能波动），单次评分建议结合锚定示例 + 多轮取中位数
- **Hy3 thinking 模式限制**：复杂评审 prompt 会触发 90s+ 思考导致断连，评测 prompt 必须极简化；这约束了 LLM-as-Judge 的"深度逐项核查"能力
- **样本集覆盖**：当前「术语误用」类攻击覆盖不足，D7 的判别力结论需在补充样本后复验

## 8. 局限与改进方向

1. LLM-as-Judge 依赖 Hy3，网络不稳定时需多次重试，成本较高；建议后续引入本地/多平台冗余
2. 主观维（D1/D4/D7）评分存在一定方差，建议扩大 N_RUNS 或引入多模型交叉评审
3. **「中」档边界模糊（已提出锚定锐化方案，待重跑）**：2 名标注员盲评（§4.2.1）κ=0.469、分歧集中于「中」档——作者把 5/6 的「中」判为「差」（偏严），独立标注员却达 94.4% 命中率（能正确用「中」）。根因是「中 ↔ 差」边界锚定在「数字错误个数」这一主观信号上。方案见 §4.2.2：把边界换成「数字对不对」这一客观信号（「中」=数字正确+非致命瑕疵，数字错误全划「差」）；需重生成 medium 样本并复跑评测与标注以确认 κ 回升
4. **补齐术语误用样本**：复验 D7 判别力（D2 已由引用审计补齐，无需再补样本）
5. 后续可引入检索增强（RAG）提升事实准确性的可核查性，并做「开卷/闭卷」对照以证伪「评测是否只是让模型抄原文」
