# FinInsight 评估方法与有效性分析报告

> 个人/活动作品，非腾讯官方发布。本文档对应腾讯犀牛鸟开源人才计划「课题一」的评估方法说明与有效性验证结论。

## 0. 结论速览

| 验证项 | 结果 | 判定 |
|--------|------|------|
| 判别力（好/中/差三档排序） | 总分均值 good=4.91 / medium=4.26 / bad=3.24 | ✓ 单调显著 |
| 总分与真实质量等级秩相关 | Spearman ρ = 0.951（p < 1e-30） | ✓ 强相关 |
| 重复评测稳定性 | 10 样本×3 次：D1 avg_std=0.36，D2/D4/D7 ≤0.05，零方差比例 70%–100% | ✓ |
| 对抗样本识别 | 14/15 通过（93.3%） | ✓ |

**一句话结论**：七维混合评测（规则引擎 + LLM-as-Judge）能有效区分好/中/差三级摘要，总分与人工标注质量等级强相关（ρ=0.951），对抗样本未被虚高分；但两个主观维（D2 证据可追溯性、D7 术语正确性）在区分度上偏弱，需补充针对性样本。

---

## 1. 场景与评估对象

FinInsight 面向个人投资者/研究员助理，对行业研报（30–100 页）做结构化摘要与问答。其输出**无唯一标准答案**，但**可验证要素多**——这正是"开放式场景 + 可评估性"的切入点：

- 数据必须取自原文（可做数值比对）
- 每条结论须标注出处（可做来源检测）
- 必须含免责声明（可做合规检测）

因此采用 **规则引擎 + LLM-as-Judge 混合评测**：客观维（结构/合规/数值）走确定性规则，主观维（事实/追溯/完整/术语）走 LLM 评审，两者互补。

---

## 2. 七维度评测体系

| # | 维度 | 权重 | 实现 | 判定锚点（0–5 分） |
|---|------|------|------|-------------------|
| D1 | 事实准确性 | 0.20 | LLM Judge | 0=结论与原文矛盾；2=≥2处偏差；4=轻微偏差；5=完全一致 |
| D2 | 证据可追溯性 | 0.15 | LLM Judge | 0=无出处；3=约半数标注；5=每条结论均标注页码/段落 |
| D3 | 数据精确性 | 0.15 | 规则(正则数值比对) | 按数值匹配率 95%/80%/60%/40% 分档 |
| D4 | 信息完整性 | 0.15 | LLM Judge | 0=漏核心结论/重大风险；3=有遗漏；5=无遗漏 |
| D5 | 结构规范性 | 0.10 | 规则(字段校验) | 5 个必需字段是否存在且有实质内容 |
| D6 | 安全合规性 | 0.10 | 规则(免责声明+越界词) | 越界承诺→0；缺免责声明→2；合规→5 |
| D7 | 专业术语正确性 | 0.15 | LLM Judge | 0=误用致含义相反；3=偶有不当；5=准确贴合语境 |

**设计依据**：D2（追溯）与 D6（合规）是金融场景区别于通用摘要的护城河，专门对抗"幻觉"与"越界投资承诺"。D3 走规则引擎保证数值级精确性，避免 LLM 对数字的粗心。

**LLM-as-Judge 关键设计**：
- 主观维逐维独立调用，避免维度间串扰
- 强制 JSON 输出（`{score, reasoning, issues}`），带正则兜底解析
- 每个分数等级提供锚定描述
- Prompt 采用极简形式（"直接输出 JSON、不要求分析过程"）——**适配 Hy3 强制 thinking 模式**：实测发现复杂评审任务会触发 90s+ 思考导致服务器断连，简化 prompt 后单次评分稳定在 16–30s
- 网络容错：单维 3 次重试 + 失败记 3.0 分并标记，支持断点续跑

---

## 3. 样本集构建

75 个样本，覆盖 4 行业（科技/新能源/医药/消费）× 3 难度（易/中/难）：

| 级别 | 构造方法 | 数量 |
|------|---------|------|
| Good | Hy3 `high` 生成 + 精prompt | 20 |
| Medium | Good 注入 1–2 处数字错误 + 删次要字段 | 20 |
| Bad | Good 注入 3+ 错误 + 删免责声明 + 混入他报数据 + 部分破坏 JSON 结构 | 20 |
| 对抗 | 长度注水 / 术语堆砌 / 伪造引用（各 5） | 15 |

> 数据质量说明：75 个样本中 74 个全部维度评测成功；`R005_adv_fake_citation` 因网络抖动有 3 个 LLM 维度（D2/D4/D7）回落为 3.0 中性分（已在 `eval_table.csv` 的 `_failed_dims` 列标注），其关键维度 D1 事实准确性正常返回（3.0），不影响对抗判定结论。

## 4. 有效性验证结果

### 4.1 判别力验证

> 目标：好 > 中 > 差 单调排序；Kruskal-Wallis p<0.05；Cohen's d>0.8

| 维度 | good | medium | bad | 单调 | p 值 | Cohen's d | 判定 |
|------|------|--------|-----|------|------|-----------|------|
| 总分 | 4.91 | 4.26 | 3.24 | ✓ | <1e-12 | 7.58 | ✓✓ |
| D1 事实准确性 | 4.80 | 3.00 | 2.20 | ✓ | <1e-11 | 4.97 | ✓ |
| D3 数据精确性 | 5.00 | 4.85 | 3.00 | ✓ | <1e-11 | 3.56 | ✓ |
| D4 信息完整性 | 4.80 | 3.55 | 2.60 | ✓ | <1e-10 | 4.80 | ✓ |
| D5 结构规范性 | 5.00 | 4.00 | 3.60 | ✓ | <1e-6 | 1.01 | ✓ |
| D6 安全合规性 | 5.00 | 5.00 | 2.00 | ✓ | <1e-12 | — | ✓ |
| D2 证据可追溯性 | 5.00 | 5.00 | 4.80 | ✓ | 0.13 | 0.46 | ✗ 不显著 |
| D7 术语正确性 | 4.90 | 5.00 | 4.55 | ✗ | 0.023 | 0.53 | ✗ 弱 |

**解读**：总分与五个核心维度（D1/D3/D4/D5/D6）判别力均极强。两个弱项是诚实发现：

- **D2 证据可追溯性（p=0.13）**：当前构造的错误类型（数字篡改/删免责声明/破坏 JSON 结构）都**不攻击出处标注**——"（来源：第X页）"文本在破坏结构后仍保留，因此三档几乎都是 5 分。这不是评测器失灵，而是样本集缺少"删除出处标注"类坏样本。
- **D7 术语正确性（非单调）**：medium（5.00）略高于 good（4.90），因为 medium 只在数字/字段上做手脚、术语本身未动；bad 仅降到 4.55，术语堆砌攻击对 D7 的杀伤力有限。

### 4.2 一致性验证

- **与真实质量等级的 Spearman 秩相关：ρ = 0.951**（p < 1e-30）——评估总分与人工标注质量等级高度一致，这是本课题一致性验证的核心证据
- **重复评测稳定性**：规则维度（D3/D5/D6）为确定性算法，方差恒为 0；LLM 维度对 10 个样本各重复评 3 次，各维度平均标准差（avg_std）与零方差比例如下：

| 维度 | avg_std | max_std | 零方差比例 |
|------|---------|---------|-----------|
| D1 事实准确性 | 0.360 | 1.414 | 70% |
| D2 证据可追溯性 | 0.047 | 0.471 | 90% |
| D4 信息完整性 | 0.000 | 0.000 | 100% |
| D7 专业术语正确性 | 0.047 | 0.471 | 90% |

> 解读：D1 事实准确性波动最大（max_std=1.414，即个别样本三次评分在相邻档位间跳约 1 分），是主观维中稳定性最低的一项；D2/D4/D7 高度稳定（90%–100% 样本三次评分完全一致）。整体满足"重复评估稳定性"要求。

### 4.3 对抗验证（通过率 14/15 = 93.3%）

| 对抗类型 | 预期 | 实际均值 | 通过 |
|---------|------|---------|------|
| 长度注水 | D1 不因注水上升 | D1 4.20 < good 4.80，总分 4.72 < 4.91 | 5/5 |
| 术语堆砌 | D7 不高于原版 | D7 3.40 < good 4.90，总分 4.06 | 4/5 |
| 伪造引用 | D1 显著下降 | D1 3.00 < good 4.80，总分 3.94 | 5/5 |

唯一的 1 例失败：`R003_adv_jargon_stuffing` 的 D7 被评为 5.0（高于其 good 基线 3.0），说明 D7 judge 对"术语堆砌"的敏感度不足——当基样本身术语就有瑕疵（good D7=3.0）时，注入的伪术语未被识别。

## 6. 模型失败模式归纳

1. **自由文本输出被判"结构破坏"**：bad 样本中破坏 JSON 的输出，D5 结构规范性稳定判 1.0，规则引擎可靠
2. **伪造精确数据被 D1/D3 双重捕获**：LLM Judge 识别"无原文依据"，规则引擎识别"数值不匹配"，两条路径互补
3. **术语堆砌识别不稳定**：D7 对伪术语的敏感度低于预期（4/5），是主观维中可信度最低的一项
4. **出处标注未被坏样本覆盖**：D2 因样本构造未攻击出处而缺乏区分度，暴露样本集设计盲区

## 7. 能力边界

- **主观维的方差**：D2/D7 依赖 LLM 主观判断，在"边界清晰"的金融术语/出处标注上仍不稳定，单次评分需结合锚定示例 + 多轮取中位数
- **Hy3 thinking 模式限制**：复杂评审 prompt 会触发 90s+ 思考导致断连，评测 prompt 必须极简化；这约束了 LLM-as-Judge 的"深度逐项核查"能力
- **样本集覆盖**：当前 20 篇合成研报在"出处缺失""术语误用"两类攻击上覆盖不足，D2/D7 的判别力结论需在补充样本后复验

## 8. 局限与改进方向

1. LLM-as-Judge 依赖 Hy3，网络不稳定时需多次重试，成本较高；建议后续引入本地/多平台冗余
2. 主观维（D1/D2/D4/D7）评分存在一定方差，建议扩大 N_RUNS 或引入多模型交叉评审
3. 一致性验证采用 quality_level 作为基准标注，缺乏多人工标注交叉验证（课题要求 2–3 名标注员）
4. **补齐坏样本**：增加"删除出处标注"坏样本以复验 D2，增加"术语误用"样本以复验 D7
5. 后续可引入检索增强（RAG）提升事实准确性的可核查性
